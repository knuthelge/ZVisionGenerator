# Frontend

The Web UI is a Svelte 5 app in TypeScript, in `frontend/`, built with Vite and pnpm into `zvisiongenerator/web/static/app/`. The built files are committed, so the package works without Node.

## Develop

```bash
make frontend-install   # install packages
make frontend-dev       # Vite dev server with hot reload
make frontend-test      # svelte-check and Vitest
make frontend-build     # build into the package; commit the result
```

You need Node.js 22.22.2+ (22.x), 24.15.0+ (24.x) or 26+ and pnpm 11 or newer. Run `make frontend-build` and commit the rebuilt files after every change: `make check` fails when the committed build is out of date.

| Folder | Holds |
|---|---|
| `src/app/` | The app shell, routing and `global.css` with the design tokens |
| `src/features/` | One folder per page: `workspace`, `gallery`, `prompts`, `models`, `config`, `jobLog` |
| `src/lib/components/` | Shared components, as `atoms`, `molecules` and `organisms` |
| `src/lib/state/` | Stores shared across pages |
| `src/lib/api/` | The API client |
| `src/lib/actions/` | Svelte actions for drags, holds and sheets |

Tests sit next to their source as `*.test.ts`.

## Confirmations

Ask the user to approve an action with `ConfirmDialog` (`frontend/src/lib/components/molecules/`), never `window.confirm`. It has no title: it shows the question, an optional line of information, and a cancel button plus a confirm button named after the action (danger-styled for destructive actions). Enter confirms (except on a focused button or link), Esc cancels, and a held key never confirms; while it is open, no other key reaches the page or a viewer underneath. Call `requestConfirm({ question, info, confirmLabel })`, which resolves `true` on confirm, or render `<ConfirmDialog>` directly when the dialog needs a body or stays open while the action runs (`pending`). A `parts` list (`{ label, size, lines }`, one block per item, shown between the question and the information) is for a question about several things; `infoTone: 'warning'` colours the information line.

**Download questions.** Every action that would download a model asks through `confirmDownloads(plan)` (`lib/state/confirmDownloads.ts`), which resolves `true` at once for a plan with no parts and otherwise shows one dialog with a block per part, its size, and the free space (`downloadConfirmText`, with **Download anyway** when it is short or `unchecked`). A job plan (`JobDownloadPlan`) comes from `planGenerate` (`POST /api/generate/plan`; the Generate form with each file as an empty part that keeps its field and file name, built by `planForm` in `lib/api/workspace.ts`, so uploads go up once, with the submit) or `planUpscale` (`POST /api/upscale/plan`); a Models-page row's `DownloadPlan` becomes a one-part job plan with `jobPlanOfRow`. The Workspace submit, `startUpscale`, the Enhance button and `downloadStore.request` all call it, so a new action that downloads adds its plan request and this one call, and stays busy while the plan is read. The plan's `licences` (each tagged with the `model` of the part it covers) become the lines under that part: `<name> (<supplier>): <summary> · <url_label> ↗[ · NOTICE ↗]`, one per record, behind the line that says downloading means agreeing to the terms shown under each model. The links open in a new tab, and Enter on one follows it instead of confirming.

Let the user choose a path on the server's machine with `PathField`, or `PathInput` (a path box with completion) and `PathBrowser` (the browse dialog) where a field needs its own layout. Each takes a browse purpose; the purposes, with their folder or file kind and accepted extensions, live in `web/path_browser.py`, so add one there for a new kind of path.

## Licence marks

`LicenceMark` (`lib/components/molecules/`) shows the terms of a model from its `licences` (the records the server sends with every model option, Models-page row and plan; the background removal models' own are `matte_licences` on the workspace payload). It renders nothing for an empty list, so a caller only passes the model's records. Without a `label` it is a 20×20 muted `ⓘ` button; with one, such as `Non-commercial`, a neutral badge button. Its name is `Licence: <name>`, `Licences: <a> and <b>` for two records, and `<label>. Licence: <name>` when labelled. There is one card, a `role="dialog"` popover with each record's name, supplier, summary, credit line and links, and two ways to open it. A mouse or pen resting on the mark for 120 ms opens it, and it closes 250 ms after the pointer leaves the mark or the card, so the pointer can cross the gap and press a link; the card is not focused then. A click, tap, Enter or Space pins it: focus moves into the card, it stays until the next click, Escape or an outside press, and a click on a hover-opened card pins it. A touch pointer never hovers (`pointerType` is `touch`), so a tap only toggles. There is no separate tooltip, and keyboard focus alone opens nothing. The popover is moved to `<body>` by the `popover` action, because the Models tables scroll sideways and clip, and carries `data-popover-nested` so a popover it opens from (the phone's setting popover) stays open. Escape returns focus to the mark and Tab past the last link closes it. Put the mark beside a control, never inside a button: the Workspace toolbar mark is a sibling of the Model `Select`, each restricted row of the phone Model popover ends with one next to its radio, and the Model chip has none.

## Audio in the Web UI

`AudioPlayer` (`lib/components/molecules/`) shows a take as a seekable waveform over the browser's own `<audio controls>`, which is the only set of controls: no custom play button, no time readout, and the waveform is `aria-hidden` and not focusable, so keys and screen readers use the native element (labelled `Play <file name>`). `Waveform` (`lib/components/atoms/`) draws the 100 stored peaks as SVG bars; in the player the played bars are primary and the rest zinc-600, and the playhead is a 2px line that follows the element's `timeupdate`. A `pointerdown` on the waveform seeks and a held drag scrubs (pointer capture). The player carries `data-own-drag`, which `OWN_DRAG` (`actions/pan.ts`) reads, and its waveform `touch-action: pan-y`, so a sideways drag on it never pages the stage or the viewer; the viewer's touch handler, the stage's `claimStageDrag` and the tile's hold all skip it. A take never autoplays, and the element is paused whenever its `src` changes (stepping the stage, paging the viewer) and when the player leaves (closing the viewer). The panel is 140px of waveform on the stage (max 880px, 44px of top padding for the corner actions), 200px in the viewer (max 960px) and 120px on a phone. The pure helpers (length labels, the `[section]` filter, the cut note, the viewer facts, the seek fraction) are in `lib/state/audioAsset.ts`.

- **Stage.** `AssetTile` in the `stage` density renders the player instead of an image, with Reuse settings and the menu at the panel's corner (no fullscreen button); the caption (`assetMeta` in `WorkspacePage`) reads words, model, length and seed, and a take that reached its model's cap (`asset.cut`) adds a warning `Badge` "⚠ Cut at 6:00" with a `Tooltip`; the cap is the model's `max_seconds` from the workspace payload's `audio_models`. Several takes of one job are players in a column.
- **Tile.** A grid tile shows the kind icon (`music`, `speech`, `waveform` for a sound), the first lines of the words (a song's style, then its lyric lines without `[section]` lines; the text; the prompt) clamped on an inner block, a 16px waveform line and the length as a `.media-tag`. A file without this app's settings, or without words, shows the bare layout (a larger icon and waveform, foot "audio · no settings"), and so does every strip tile. No tile plays.
- **Viewer.** The player, then the words in labelled blocks (a song's style and lyrics, the text, the prompt) that scroll with the stage; Generation (kind, model, voice, length with "(cut at the cap)", seed) and File (format, rate, channels, size). `upscale` and `extend` are `null` on a take, so the bar offers neither.
- **Job card.** A job with `media_type: "audio"` counts `take`s, its preview slot is 4:1 with `AudioAurora` from the moment the job leaves the queue (waiting at zero progress while it enhances and loads, then following `audio_progress`) (the last take's waveform shows between takes), and its phases come from `audio_progress` events kept as `job.audio` (`phase`, `step`, `total` or `null`, `part`, `parts`): `audioRows` in `jobView.ts` gives a song one row per phase (`musicRows`: Planning, Writing the song, Rendering, Finishing), each done, current or next, and speech and a sound one row (`singleRow`): speech reads like the preview's note ("Reading part 2 of 4 · 0:16") and a sound its steps ("Step 5 of 8"). Writing the song shows the time written so far; a phase without a total (the plan, a Mac render) shows only its label and an indeterminate bar. The header bar and the batch segments follow `audioFraction`, which is Aurora's `auroraProgress`, so the bar only moves forward. An out-of-memory failure shows the server's own message.

  `AudioAurora` (`lib/components/molecules/`) is one `<canvas aria-hidden>` of ribbons over a starfield: the made part glows ahead of a soft playhead, and the colours come from the CSS tokens when it mounts (`AURORA_TOKENS`). Nothing pulses; drift cycles are 10 to 30 s. The sky carries the stage of the take: `auroraStage` maps the latest `audio_progress` (none yet is `wait`) to `wait`, `plan`, `write`, `synth` or `decode` (`Sampling`, `Song tokens` and `Speech tokens` are `write`; a ready take is `decode`), and `stepStageMix` / `stageWeights` cross-fade the stages over 750 ms of real time (`STAGE_FADE_S`), so `stageLook` blends one `SkyLook` per stage: haze, stars, a horizon glow, a far ribbon layer and a centre line, plus a few ribbon parameters. Speech tightens each decoded part toward the outline (`tightnessAt`). `skyBoost` scales the sky's opacity and size up on a narrow slot, 1 at 520 px and wider to 1.8 at 366 px, so the stages stay apart on a phone. The maths is pure in `audioAurora.ts` (the estimated progress per kind: Music by phase shares, Speech by frames against the part's total, Sound by steps; the stages; the ribbons; the landing), the painter is `audioAuroraDraw.ts`, and the component runs the clock at 30 frames a second at most. It stops while the tab is hidden, the slot is off screen, the job is paused or ended, and after the landing. With `prefers-reduced-motion` it redraws on each `audio_progress` only, one still per stage (no cross-fade), and swaps straight to the waveform. On `generation_finished` the ribbons collapse onto the peaks (650 ms) and the canvas gives way to `<Waveform>`, whose last landing frame is the same bars.
- **Models page.** An Audio models panel follows Video models, shown only when the inventory lists `audio_models`. A row has the label with its `LicenceMark`, the kind, the disk use, the GPU memory badge and Download or Delete; downloads go through `downloadStore` with kind `audio` and its dry-run plan, so the confirm dialog shows the model's licence lines.
- **Memory badge.** An audio model's fit is the GPU's alone, so `ModelStatusBadges` words an estimate without `system_gb` as GPU memory only.

**The Audio tab.** It opens on the kind it was left on (`draft.audioKind`) and takes the model last chosen for each kind (`draft.audioModels`); a machine that runs no audio model gives the tab back to Image (`hydrateFromContext`). `lib/state/audioDraft.ts` holds the pure parts (`hydrateAudio`, `audioPrefill`, `replacesVoice`, the length range), `lib/state/musicMode.ts` mirrors the song-or-instrumental rule of `music_mode` and is tested against `tests/audio/music_mode_cases.json` with the Python rule, and `features/workspace/audioView.ts` derives, once per render, what the open kind sends and the one reason Generate is off (`AudioView`, with `VoiceView` for the Speech voice), which `buildFormData` (`audioFormData`), the Settings footer, the phone composer and the chips all read.

- **Toolbar.** The Kind control (a `Segmented` with icons, built from a `KindChoice` with `AUDIO_KIND_INFO` from `kindInfo.ts`; `Segmented` options take an `icon`) comes first, then the model `Select` of the kind's presets, the model's `LicenceMark`, the memory badge and "Not downloaded". Presets, Quantize and LoRAs are not rendered.
- **Compose.** `AudioCompose.svelte` replaces the prompt boxes: Music is a Style over an optional Lyrics with a status line from `musicMode` (the model row's `instrumental_sections` is the list an empty box stands for), Speech a Text with its character count and Sound a Prompt. Its tools row holds Recent prompts only, one list per kind (`mode` `music`, `speech` or `sound`); a music entry brings its lyrics back with its style.
- **Settings.** `VoiceSection` comes first for Speech, then Sampling with Batch, Length (s) for Sound (from 1 s to the model's `max_seconds`, 10 s to begin with) and Seed. On a phone the chips are Kind, Model, Voice or Length, Seed and Batch, then All (`audioChips`); the Kind popover is three radio rows with a line each, the Model popover ends each restricted row with its mark, and `VoicePopover` repeats the section.
- **What a Generate sends.** `audioFormData` builds the fields Copy CLI reads for the open kind only: `mode=audio`, `workflow`, `model`, `prompt`, `lyrics` (Music), `seconds` (Sound), `voice_file` or `voice_path` with `voice_text` and `voice_consent` (Speech, from a recording), `runs` and `seed`. The tick goes as a hidden `false` and, once ticked, `on`. The plan (with the recording's body left out), the download dialog with its licence lines and the submit all read this one form. Copy CLI reads it too, so the command carries `--voice-consent` while the box is ticked.
- **Footer reasons.** One at a time in `ui-alert-warning` (`id="ws-generate-reason"`, Generate's `aria-describedby`), in this order: the style, the text or description, a recording to choose, its length (3 to 30 s for Higgs), what it says, the tick, then text over the model's cap. Generate is disabled while one shows, and so is ⌘↵. The phone's composer shows it above its row.
- **The speaker's consent.** The tick lives in `lib/state/voiceConsent.svelte.ts`: in memory only, never in the draft, an address or a job's settings. The tick follows the voice: a new recording (`draft.setVoice`), Reset and a prefill that replaces the voice (`audioPrefill` returns a `voice`: a Speech Reuse, Use as → Voice, Load settings, a link) clear it, while a music or sound prefill leaves the voice and its tick alone; a reload forgets it. A Use as → Voice from a take made in the model's own voice (no `voice_clone`) marks the voice `exempt`, so no tick is asked for; a reload forgets that too and the tick is asked for once more. The Voice section is `InspectorSection id="voice"`: *Any* or *From a recording*, the file slot, **What it says** and the tick.
- **Held uploads.** The recording is held in `heldUploads.voice` and persisted in the `audio` record of the upload store (its `track` field), so it survives a visit to the Gallery and a reload, like the Video tab's audio track. Reset clears the voice, the held recording included.
- **Top bar and checkboxes.** At 1000 px and below `TopNav` hides the wordmark (the mascot and the screen-reader name stay) and tightens the tab and icon padding, so four workflow tabs stay on one row from 740 px. An unticked `.ui-checkbox` has a 1px `zinc-500` ring.

**Use as for takes.** The asset menu and the viewer's Use as list, for an audio take, **Audio track** (hint "Video tab, from 0 s"; disabled with the reason when the Video model cannot follow a track) and, for a speech take, **Voice** (hint "Speech, text filled in"; disabled with "Use a take of 30 s or less as a voice" over the speech model's `max_voice_seconds`, 30 s when unknown). Both go through the prefill a Reuse uses (`router.navigate('workspace', params)` from the Gallery, `applyPrefill` on the Workspace) with `use_as` set, so only that one slot changes. The params are the contract the Audio tab reads:

| Target | Params |
|---|---|
| Audio track | `workflow=txt2vid`, `audio_track_path` (the take's file), `audio_track_start=0`, `use_as=audio_track`; the draft's other slots, its first frame included, are kept and only the Video tab's held upload goes |
| Voice | `workflow=speech`, `voice_path` (the take's file), `voice_text` (the take's text), `use_as=voice`, and `voice_clone=true` only when the take was made from a recording (`has_reference_voice`) |

`voice_clone` tells the Speech tab to show the consent tick: a voice that is itself a clone is a person's, while a take the model chose the voice of (*Any*) needs none. The server decides the same way when the job is submitted (`voice_needs_consent`). The speaker's consent is never in a URL or a draft.

## Toasts

Report the outcome of an action with `addToast(message, type, options)` from `$lib/state/toasts.svelte`. One toast shows at a time at the bottom centre of the page content (pages with a fixed left sidebar set `--toast-inset-left`); the rest wait their turn, shown as "+N". A repeat of a waiting or showing message merges into it ("×2"), and an error goes ahead of every non-error. Each tone has a default time on screen (success 2.5 s, info 4 s, warning 7 s); errors stay until dismissed, or give way after 8 s once other toasts are waiting, and hovering or focusing a toast pauses it. Pass `{ action: { label, run } }` for one follow-up such as Retry, and `{ timeout }` only when the default doesn't fit. An action that acts on a page must not outlive it: keep the id `addToast` returns and call `dismissToast(id)` in the page's `onDestroy`. The exception is the download lane (`lib/state/downloads.svelte.ts`): its store raises the done and failed toasts, and their Retry runs the store's request flow rather than page code, so they stay after the page that began the download is gone. Raise one toast per action, and skip it when the screen already shows the result.

## Requests and errors

Send requests through `api` in `$lib/api/client`, which throws `ApiError` with the HTTP `status` and the server's `detail`. Show a failed request with `errorText(err, fallback)`, never `err.message`, which holds the method, path and raw body. Offer Retry only when `isRetryable(err)`: a 4xx means the server refused the input, and the same request fails the same way again.

## Design system

The Web UI has one design system. Its tokens live in `@theme` in `frontend/src/app/global.css`, and its component classes are the `ui-*` classes in the same file. Build pages from the shared components in `frontend/src/lib/components/` (`Button`, `Input`, `Select`, `Toggle`, `Badge`, `Panel`, `Segmented`, `ActionBar`, `PageHeader`, `KeyValueList`, `Alert`, `EmptyState`, `InspectorSection`, `InspectorRow`) or, where no component fits, the `ui-*` classes (for example `ui-chip`), rather than styling elements by hand.

- **Size:** controls are 28px (`h-control`), small ones 22px, rows 30px. Buttons that sit together share one height; inside an `ActionBar` every button is 36px and the one marked `main` takes the remaining width.
- **Type:** four sizes: `text-meta` (11px), `text-ui` (12px), `text-content` (13px), `text-title` (16px), plus `text-display` (30px, 24px on compact screens) for the first-run welcome headline and the recommended model's name only. Nunito (`font-heading`) is for titles, area names and the main action; monospace is for numbers, paths and shortcuts.
- **Labels:** field and row labels are sentence case (`ui-label`). The one small-caps style (`ui-area-label`) names areas: panels, sections, table headers and menu groups.
- **Shape and surfaces:** corners are 4px for chips and badges, 6px for controls and 10px for containers. Overlays (menus, popovers, tooltips, toasts, dialogs) use `bg-overlay`, darker than any page surface, with a faint ring and never a drop shadow; `bg-raised` is for section header bands and `bg-fill` for the prompt box.
- **No borders:** containers are separated by shade, and buttons, fields, chips and badges are filled shapes. Dividers between rows and sections stay. Draw an outline only where it means something: focus, a field with an error, the selected tile, and the dashed edge of drop zones and add buttons. Segmented controls are a recessed well with the chosen option as a lighter pill.
- **Main action:** each section (a bar, panel, form, dialog or popover) has at most one main action, a `primary` button: teal fill and a bold Nunito label. Every other button in the section is secondary.
- **Reference pages:** Config and Models centre their content at `max-w-page` (1200px), with the page bar lined up to it. Settings use label-left rows (`FormField layout="row"`), and tables use `ui-table-comfortable`.
- **Colour:** neutrals are Graphite greys with no tint. Teal means on, selected or the main action; coral (`accent-coral`, Blob's beret) marks `$snippets` and amber `{a|b}` choices; red is for errors and destructive actions, which always show red text. Info messages stay teal, never coral. Text is at least 4.5:1 on every surface. Use tokens, never raw palette classes or colour literals; `make check` fails on them.
- **Focus:** every control shows the same 2px teal outline with a 2px offset.
- **Touch is a layer, not a breakpoint:** `@media (pointer: coarse)` in `global.css` raises the size tokens (controls 40px, small controls 32px, rows and action bars 44px, the switch 40 × 24) at every width, so an iPad in the desktop layout gets finger-sized targets and a mouse keeps the desktop density. Build sizes on the tokens, never on literal pixels, so they follow. Numbers get − and + steppers (`InspectorNumber`, press and hold to repeat) because a label cannot be scrubbed when a drag scrolls; `InspectorRow` skips scrubbing on a coarse pointer. The `layout` store (`lib/state/layoutMode.svelte.ts`) tells components the composition (`compact | tall | wide`) and whether the pointer is coarse.
- **Hover only where there is hover:** a touch screen keeps `:hover` on whatever was tapped last, so every `:hover` rule sits inside `@media (hover: hover)` (`make frontend-hover-check`, part of `make check`, fails on a bare one; Tailwind's `hover:` variant already does this). A finger gets an `:active` pressed state under `@media (hover: none)` instead, and anything a mouse reveals on hover is always shown under `(hover: none)`. On a phone, fields are at least 16px so focusing one does not zoom the page, and the page never scrolls or bounces (`overscroll-behavior: none` on `html` and `body`).
- **The visible viewport:** `lib/state/viewport.ts` (started in `main.ts`) sets `--app-height` and `--app-top` from `window.visualViewport`, and puts a page the browser scrolled back at the top when no field is being edited. The app root and every full-screen layer use `.ui-viewport`, which is fixed to those values, so they sit above an on-screen keyboard (iOS ignores `interactive-widget`) and follow Safari's toolbar at once. Build full-screen layers on `.ui-viewport`, never on `inset: 0` or `100vh`.
- **Three compositions of one Workspace:** the same panes (`ComposePane`, `SettingsPane`, the toolbar, the stage, `GalleryStrip`) are arranged by `layout.mode`. *Wide* (1024px and up) is the sidebar beside the stage. *Tall* (640 to 1023px, a portrait tablet) puts the stage and strip over Compose and Settings side by side. *Compact* (under 640px, or under 500px tall) makes the stage the screen: a `TopStrip` and `NavDrawer` replace `TopNav`; a `SettingsStrip` of chips (`settingsChips.ts`) opens one `SettingPopover` at a time, All opens `SettingsPane` in a `Sheet`, and a composer at the foot hosts `ComposePane` folded or open. Everything stays inside the Workspace form, so every field submits in every composition. A running job shows `JobPreview` large with `JobCard` beside it on wide and tall and `JobBar` over it on compact; `ActionMenu` and `Modal` render as a `Sheet` on compact. Nothing is hidden behind a phone pattern on a wide screen.
- **Stable frames:** nothing moves under a finger while a page loads. *The frame first:* a page draws its complete frame synchronously from its composition (bars, strips, panels, the grid, action rows) and requests only fill it; a loading state lives inside the slot it is loading (placeholder chips in `SettingsStrip`, the disabled actions of `AdminPageShell`, the Gallery's placeholder tiles) and never changes the height of anything around it. *Pages remember:* a page component is rebuilt on every visit, so what it loaded lives in `lib/state/pageMemory.ts` (the Workspace context, the Gallery view with its scroll position, the inventory, the config); the page adopts the remembered value on mount, draws it at once, then asks the server again and replaces it. *Anchors do not move:* the top strip, the composer, the settings strip and page bars keep their place and size; content that changes size changes inside a box reserved from the start. A new page follows all three, and page switches stay a hard cut, which is what a native tab switch does.
- **One Gallery:** the strip on the Workspace, the stage's stepping through earlier outputs, the Gallery page and the viewer all read `lib/state/gallery.svelte.ts`, which keeps one list per query (`filter` and `sort`). The default query is the strip's and the stage's and the store loads it; the Gallery page loads its own query's pages and commits them with `setView`, so `removeAssets` and `mergeOutputs` reach every list, a visit comes back where it was, and the page's first visit shows the strip's list. There is no history route or store; `/api/gallery` serves both.
- **One viewer, native on each device:** `molecules/AssetViewer.svelte` is a panel over the page on wide and tall layouts (a backdrop that closes on click, the details column beside the image) and the whole screen on compact. It takes the tile that opened it (`origin`) and flies a copy of the thumbnail between the tile's box and the image's box on open and close (`viewerFlight.ts`, a FLIP on the transform), with the thumbnail standing in until the image has loaded. On touch, a track of three panes follows a sideways drag and settles to the neighbour before the index changes (`viewerPager.ts` decides from offset and velocity); a pull down shrinks the image and clears the backdrop (`--pull`), and lets go into the tile through the same flight; a pull up opens the details as a half sheet in flow under the image; one tap hides the chrome. A hold on the image (`actions/hold.ts`, which swallows the click the lifting finger makes wherever it lands) or a right-click on a tile or the image opens the asset menu, anchored at the pointer through a 1px anchor. The viewer is an escape layer, so Escape closes it, the shortcut list first.
- **One sheet, and drags that follow the finger:** every sheet on a phone is `molecules/Sheet.svelte` (the Job and All settings sheets, the enhancer, menus, dialogs): it slides in and out, is as tall as its content up to the screen under the top strip, and pulls down to close through `actions/sheetDrag.ts`. The grab bar and head carry `data-sheet-handle` and always pull; the body pulls once its content is at the top. The `SettingPopover` and the viewer's details use the same action. Drags are built on `actions/pan.ts`, which decides on the first movement whether a touch is the surface's (and then cancels every move, so the browser cannot start scrolling under it) or the page's; deciding later loses to native scrolling on iOS and Chrome. Its pure helpers (`lockAxis`, `releaseVelocity` from the last 80 ms, `rubberBand`, `canScrollToward`) carry the decisions and are unit-tested. A press and hold is `actions/hold.ts` (fingers and pens only; it marks the node `data-holding` with `--hold-ms` while held, so `.ui-holdable` fills a bar along its foot, and swallows the click and the browser's long-press menu once it fires; only the first finger down holds, and a second finger anywhere on the page cancels the hold, so a pinch never opens a menu): Generate's new-seed menu, the asset menu on every `AssetTile` and the viewer's stage use it. The `NavDrawer` swipes closed on the same tracker, and the Workspace stage uses it to follow the finger sideways through history and up to the Gallery (`features/workspace/stageSwipe.ts` decides the outcome, and a trackpad's sideways wheel steps once per gesture). The Prompts page arranges sets, entries and snippets with pointer events, not HTML drag and drop (which never fires for a finger): `reorderDrag` in `features/prompts/dragDrop.svelte.ts` starts at once from a grip for a finger and after a few pixels for a mouse, and `dropTargetAt` reads the drop zones from `data-dnd-entry`, `data-dnd-set` and `data-dnd-snippet` under the pointer.
- **Workspace tabs and image slots:** the top bar has three tabs, `image`, `video` and `audio` (`NavTab`, `navTab(workflow)` in `lib/state/workspaceTab.ts`); `visibleTabs` shows Audio when the contract lists a music, speech or sound workflow. Extend is a kind of Video, chosen with the Kind control (a `KindChoice` with `VIDEO_KIND_INFO`; the phone's `kind` chip) and offered when the contract lists `extend` (`videoKinds`); `draft.setVideoKind` switches it and `draft.state.videoKind` remembers the kind Video was left on, as `audioKind` does for Audio. `workspaceTab(workflow)` is still the slot a workflow keeps its images and audio track in, and gives `extend` a slot of its own. `draft.state.workflow` is derived from the tab and its start image: `img2img` or `img2vid` when the start image is set and the model takes one, otherwise `txt2img` or `txt2vid`; on the Audio tab it is the open kind (`music`, `speech` or `sound`), whatever the images are. The prompt text is kept per tab: Image and Video each hold their own, and Video's two kinds share one. Uploads persist in IndexedDB (`lib/state/uploadStore.ts`, `lib/state/heldUploads.svelte.ts`), and Generate waits until `heldUploads.restored`. What a model takes for images is answered once, by `imageSupport` (`lib/state/imageSlots.ts`); the workflow, the Images section and the Use as menu all follow it.
- **One scope table:** every field of `DraftState` has exactly one owner in `FIELD_SCOPE` (`lib/state/resetScope.ts`: the open tab's slots, `settings`, `shared`, `model`, `text`, the enhance options of each mode, the Audio tab's text, length and voice, `memory`, `ui`, `preset` and `derived`). A field added to `DraftState` without a scope fails `svelte-check`. A transition is a list of scopes: `RESET_SCOPE` holds the one of each tab (a new `WorkspaceTab` fails until it has one), and `draft.resetSelections` takes the values `defaultsFor(ctx, state, extendSource)` resolves for those scopes (the static defaults, then the model's with its cleared fields and capability gates, then the values derived from the draft: the Extend length and track from the source, a sound's length within the model's range) and leaves every other field as it was. `REUSE_SCOPE` is the same per tab plus the text, the model (with its LoRAs and quantization) and, on Extend, the source: `loadFromUrl(..., { exact: true })` puts those scopes at `defaultsFor` before it sets the params, then fits the size to the model. Only a Reuse and a Load settings are exact: `reuseParams` marks a Reuse with `reuse=true` (a link from the Gallery arrives as params) and `loadJobSettings` adds it, so a Use as (`use_as`), a keepSettings prefill, a deep link and a preset keep applying only what they name. The Audio tab's exact prefill puts back Batch and Seed only; its kind's own fields come from `audioPrefill`. A scope that holds uploads also forgets them: `slotsImage`, `slotsVideo`, `slotsExtend` clear the held files of their tab and `voice` clears the recording and the speaker's tick. Anything a new field needs beyond that goes into `defaultsFor`, not into a keep list.
- **One settings table:** `SETTING_ROWS` (`features/workspace/settingRows.ts`) lists the Settings pane's rows with their draft keys, the phone chip they belong to and when they show. The changed dots and the Reset badge of `SettingsPane`, the chips' `changed` flags and the phone's *All* count, and each popover's Reset all read it, so they agree. A setting added to a setting scope needs a row; a test compares the two. The LoRAs of the Audio tab are none: entering it remembers the family's LoRAs it comes from and leaving it brings back the ones of the family it goes to (`_swapFamilyLoras`), and `generateBlock` ignores the chips there. The quantization of the image model is remembered in `lastImageQuantize`, as `lastImageModel` remembers the model, because the video workflows clear it.
- **One image view:** `imagesView` (`features/workspace/imagesView.ts`) derives from the draft, the model's capabilities and the held uploads which images the open tab uses. `WorkspacePage` computes it once and passes it down, so what is shown, Generate's gating (`block`) and what `buildFormData` sends (`sent`) always agree. References are rows numbered by position. A row whose file is gone stays, so the prompt's "image 2" keeps its meaning, and blocks Generate. The Workspace flags missing paths with `POST /api/references/check`.
- **One audio track view:** `audioTrackView` (`features/workspace/audioTrackView.ts`) does the same for the Audio track of Video and its Extend kind: each slot keeps its own `audioTrack…` or `extendAudioTrack…` draft fields and held file, and the view says whether the track is in effect (set, on a model with the capability), what `buildFormData` sends and whether a lost upload blocks Generate. While a track is in effect `workspaceCapabilities` turns `showAudio` off, so the Audio switch, the enhancer's Sound options and the `audio` field all go, and turns the Upscale controls off on a model that cannot upscale a clip made from a track.

## Discover LoRAs

The drawer lives in `features/workspace/discover/`: a side `Modal` (a `Sheet` on a phone) mounted by `WorkspacePage`, so it shares the page's draft and download state. `discoverView.ts` holds its pure logic (the target model, a LoRA's status, filters, tiles, details and the footer); requests go through `lib/api/discover.ts`. The Models page opens it with the hash `#/workspace?discover=loras`.

- **Downloads.** A LoRA download is a lane item of kind `lora` in `downloadStore`. `lib/state/loraDownloads.ts` turns the lane into what a chip shows and what holds Generate back; a failure wins over a download still on its way. Removing a chip never stops a download. A failed item stays in the store after the server stops listing it, until it is retried or its LoRA deleted, so a red chip doesn't turn ready by itself.
- **Trigger words.** `features/workspace/triggerMenu.ts` builds the Triggers menu from the text Generate sends and inserts a chosen word at its start; nothing is written into a prompt without a choice.
- **Toasts on a phone.** `actions/dockHeight.ts` publishes the height of the phone's controls as `--toast-dock`, so a toast never covers them.

## The mascot

Blob is one SVG, `atoms/Mascot.svelte`, with a `mood` (13), a `tool` (`brush` or `clapper`), a `size` and an optional `progress` (0 to 1) for the creating canvas. Every mood is CSS on the same parts, and a mood change blends from the pose on screen (`blendInto`), so an idle mascot costs no script. Below 48 px he is drawn in a simpler form (`data-simple`: bead eyes, no hands, tool, brows or effects), which is also what `public/ziv-icon.svg` shows.

- **Effects.** The creating canvas (`mascotArt.ts`) is drawn at the step the job's progress gives (`tileStep`; the last step comes at `FINISHING_FRACTION`, where the mood turns to finishing). While no progress is passed (between the items of a batch, in the stages around generating) it holds its last step. `WorkspacePage` passes `mascotProgress(job)` to the spots on a job. The mood effects (the thought bubble, the pixel Zs, the creating and finishing canvas, the confetti) are always mounted and shown by their mood's opacity rule, so the pose blend fades them in and out with everything else. Each has a still frame under `prefers-reduced-motion`.
- **Spots.** `MascotSpot` wraps him for a place on a page and passes `progress` through; spots that share a `travelKey` hand him over. `mascotFlight.ts` holds the transitions: a spot with no previous spot is sampled in (Denoise in, 800 ms), a spot that follows another receives him as a stream of 16 x 16 pixels along an arc above the page (Latent stream, up to 1 s). A spot that no other spot takes over simply disappears. Call `rememberMascotSpots()` before a change that swaps spots, so the stream starts where he was.
- **Canvas only in transitions.** `mascotCanvas.ts` bakes the SVG with each part's current pose, rasterises it once (a hand-off bakes the old spot's pose as he leaves and rasterises it only if a spot takes him over) and draws the effect on a canvas fixed on the `--z-mascot-effect` layer (over the page, under the viewer, sheets, dialogs and toasts; over the dialog or sheet his spot sits in), sized to the area the effect covers (his box, or both spots and the arc between them for a stream) and removed at the end. The spot is hidden until the effect hands over. Where the browser can animate but has no canvas a spot pops in with a short scale-up; where it cannot animate, and under reduced motion, he is simply there, with no transition.
- **The logo.** `MascotHome` draws him at 1.39 times the logo's size, offset so his body lines up with the static icon; his dashed outline uses the same silhouette.
