# Backlog from the v1 review

**Status:** Backlog (2026-11-12)

Findings from the pre-v1 codebase review that were verified but deliberately left out of v1. Each is small enough to pick up on its own; none has a proposal of its own. Items are grouped by area, and each says what a user sees, where it sits, and what the fix would be. Decisions taken at the review are noted. Every item was re-checked against the code on 2026-11-12; line numbers are from that check.

## Web UI

- **The Gallery and the browser tab don't show a finished job.** On every page but the Workspace a finished job gets a toast and a mascot reaction (`App.svelte`, the app-wide `subscribeLifecycle`). The Gallery grid doesn't refresh while it is open: only the Workspace merges new outputs (`WorkspacePage.svelte`, `handleJobComplete`), and `GalleryPage.svelte` has no lifecycle subscription. The tab title, favicon, sound and browser notifications don't signal anything. The out-of-tab part is covered by [Know when a job is done](job-notifications.md); the Gallery refresh is not.
- **A stalled SSE stream in a visible tab is never detected.** Returning to a hidden tab reattaches the stream (`watchVisibility`, `lib/state/job.svelte.ts`), and `attachJobEvents` closes the old stream first. A tab that stays visible with a dead connection is still stuck: `sse.ts` reacts only to `onerror`, the 4 s `/api/jobs` poll returns early while the followed job is non-terminal (`followActive`), and `lastEventAt` (set in `lib/state/jobPhases.ts`) is only shown on the job card. The server's 10 s `: keep-alive` is an SSE comment, which `EventSource` never hands to JS. Fix: send a named heartbeat event, and treat a long silence or a poll that no longer lists the job as a reconnect. Not checked in a browser: whether a laptop wake or a Wi-Fi change keeps the tab visible, so `visibilitychange` never fires.
- **Four failure toasts drop the server's reason**, against the documented `errorText(err, fallback)` rule: gallery delete (`GalleryPage.svelte`, the single and the bulk delete), workspace delete, remove from queue and clear queue (`WorkspacePage.svelte`). The 404 details name an asset path or a job id, so the wording needs a choice; clear queue has no server detail, so its fix is wording only. Decision: skipped for v1.
- **Uploads accumulate for good** in `<output>/.web_uploads/` (`web/server.py`, `_save_upload`), as `<sha256>.<ext>` or `<sha256>/<name>`; identical content is saved once. Start and reference images, video frames (`video_frame_api.py`) and audio and voice uploads all land there, and nothing ever removes them. An image submit saves its uploads before validation, so a refused submit leaves its files behind. Recorded settings point at them for Reuse, so a cleanup must keep referenced files.
- **Background-thread failures in the download lane and video conversion are not logged.** The download lane keeps only `str(exc)` (`web/download_lane.py`) and silently passes on a failed cleanup; video conversion keeps the last `Error:` line of a failed converter and discards the rest of its output (`web/video_conversion.py`). Fix: `logger.exception` in both `except` branches, log the cleanup failure, and log the converter's captured output and exit code, so a bug report has the details in `ui.log`.
- **Deleting `ltx-4` on Windows/Linux can delete `ltx-8`'s files** (found 2026-10-26). Both aliases point at the same ~104 GB diffusers download; `ltx-4` only adds a 4-bit stored copy. `model_delete_target` (`web/model_delete.py`) keeps a shared download only while another alias has stored copies, so when `ltx-8` was downloaded but never run, deleting `ltx-4` removes the download and the `Lightricks/LTX-2.3` companion files `ltx-8` loads from, and the dialog never names `ltx-8`. A used `ltx-8` already keeps them. Decision: "last holder takes the shared files" (not implemented). An alias holds a shared download once it was used (a job ran with it, or its row's Download was pressed) and not deleted since, recorded in the app database. Deleting a holder while another holder remains removes only its own files (its stored copies) and shows it as not downloaded; deleting the last holder removes the download too; an alias that was never used does not hold it. The same rule could replace MOSS-Image's built-folder rule. Its own standard run (discovery, PRD, review).
- **Other websites can make the server list folders** (found 2026-11-06 while reviewing the file picker). `GET /api/browse` and `GET /api/browse/places` are plain GETs, and `request_guard` lets every GET through, so any page the user visits can point an `<img>` at them. It can't read the answer (no CORS), but on Windows a `\\host\share` path makes the server open an SMB connection to that host. Fix: refuse `Sec-Fetch-Site: cross-site` and `same-site` on both browse routes, as the file picker's preview routes do, with a test per route. Fetch Metadata is only sent to HTTPS and localhost, so this protects the default `127.0.0.1` setup, not `--host local` over plain HTTP.
- **No test ties the frontend's SSE listener list to the server's event names.** `sse.ts` hand-lists the event types in a local constant; a renamed or new server event is dropped silently. Today every listened name is emitted except `progress_text`, which has no producer (see Dead code). The test: every listened name is emitted, and every emitted name is listened to or on an explicit ignore list (`job_submitted`, `generation_started`, `workflow_finished`).
- **A second toast can expire unseen** (found 2026-11-12 testing the Gallery bulk actions). The toast stack shows only the oldest toast with a "+1" badge, and the hidden one keeps its own timer, so pressing Delete a few seconds after Download can drop "Deleted 3 files." before it is shown. Fix: start a toast's timer only once it is visible, or show the stack.
- **Viewer toolbar icons are hard to read** (found 2026-11-12 in a user walkthrough of the Gallery mockups). Below 1100 px the toolbar is icon-only: **Use as** is a bare image icon, **Upscale** reuses the expand arrows a tile uses for "view full size", and **Reuse settings** looks like refresh. The shortcut hint beside Details reads as a stray "I". Fix: distinct icons for Upscale and Reuse, labels on the menus that need them, and shortcut hints in tooltips only.
- **Double-decoded asset IDs** (found 2026-11-12 reviewing the Gallery bulk actions; on main too). `normalize_asset_id` (`web/gallery.py`) calls `unquote` on values Starlette has already decoded, so a file named like `50%20off.png` is read as `50 off.png`. The Gallery then can't show it (`/media` answers 404), can't star it (the star is stored under the decoded name, so the file never shows as starred) and can't bulk-delete it (the request reports success but the file stays). Fix: drop the `unquote`.
- **Stars are lost on an outside rename** (found 2026-11-14). A star is keyed by path alone, so a file renamed outside the app loses it, and a new file that takes the old name shows it. Fix: store a size and sampled fingerprint when a file is starred and match it only when a starred path goes missing (as TMSU does). Don't prune stars to the listed IDs: changing the output folder would wipe them.

## CLI

- **Ctrl+C prints a full traceback** in every CLI, often from inside torch or hf_xet. No entry point catches `KeyboardInterrupt`, and `app_log`'s hook passes it to the default hook. In `ziv video` the first-use model download runs inside model load, where no key stops it, so Ctrl+C is the normal way to stop a 30–100 GB first download (`q` works during prompt enhancement and generation, with or without `--review`). Harmless (terminal restored, download resumes). Catch `KeyboardInterrupt` at the entry points and print one line; the `app_log` hook alone isn't enough, since it isn't installed with `ZIV_LOG` off.
- **A custom image alias with a per-platform map lacking this platform crashes `ziv image`** with a `ValueError` traceback (`image_cli.py`, `resolve_model_path` not wrapped); `ziv video` catches it and turns it into a `parser.error`. Only custom aliases.
- **The CLI H3 converter prints a traceback on network and disk-full failures** while it fetches the text encoder and turbo LoRA (on macOS, the components and LoRA); the Windows/Linux base-repo download is already wrapped. `converters/convert_checkpoint.py` catches only `ValueError`, `FileExistsError` and `RuntimeError`; `utils/hf_snapshot.py` does not wrap Hub errors (httpx errors, so a wrap must catch more than `OSError`), and a full disk is an `OSError` from the writers. Nothing checks free space before writing a 12–38 GB converted folder. The Web UI path shows the last stderr line and is fine.
- **ffprobe is not checked.** `ensure_ffmpeg` checks ffmpeg only. With ffmpeg but no ffprobe, `ziv video --extend` reports `[Errno 2] ... 'ffprobe'`, and `ziv video --audio-file` and speech with a recorded voice traceback, the audio path with a misleading "needs consent" message. Fix: check ffprobe in `ensure_ffmpeg`, or have `ffprobe_json` turn a missing binary into a `RuntimeError` as it does other failures.
- **A prompts file that is a directory or unreadable still tracebacks.** `ziv image -p <directory>` or an unreadable file: `image_cli.py` turns only `FileNotFoundError` into "Prompts file not found … Provide --prompt or a valid --prompts-file", and `Path.read_text` raises `IsADirectoryError` or `PermissionError`. `ziv video` checks `Path(...).is_file()` first, which covers a directory but not an unreadable file. Fix: catch `OSError` in both CLIs, together with the next item. Decision: skipped for v1.
- **The prompts-file message lives in both CLIs.** The same sentence sits in `image_cli.py` and `video_cli.py` behind different checks (an exception in one, an `is_file` pre-check in the other); `docs/reference/troubleshooting.md` and three test assertions repeat it. One read-and-check helper in `utils/prompts.py` that both CLIs call would fix this and the previous item together. Decision: skipped for v1.

## Generation and backends

- **One exception in an image batch aborts the batch with a traceback.** No image stage returns `StageOutcome.failed` or `.retry`, so the image runner's failure and retry branches are unreachable and nothing in the loop catches exceptions (`image_runner.py`); the video runner catches per iteration. In the Web UI the job ends failed with a one-line reason and the traceback goes to the log. CUDA image and LTX have no `torch.cuda.OutOfMemoryError` handling (SeedVR2 and H3 do). Decision: keep as is for v1.
- **Pin the unpinned image aliases and SeedVR2 repos.** `zit`, `klein9b`, `klein4b` and `krea2` and the SeedVR2 weights (`numz/SeedVR2_comfyUI`, `AInVFX/SeedVR2_comfyUI`) are listed in `utils/model_metadata.yaml` without a revision, so an upstream change reaches users unchecked. Pinning needs the loaders to take a revision: `image_model_detect.py:98-100` refuses a pinned reference for every family but Ideogram 4, and the image loaders pass no revision on. Fix: let the image and SeedVR2 loaders pass the revision to the Hub, lift the refusal, then pin each alias and repo to a checked commit.
- **Extend refuses clips made with the built-in `--upscale 2`** and says "extend the original instead", but the built-in upscale discards the half-size render (`utils/video_extend.py`, `provenance.py`), and the message's reason (the size isn't one the model generates at) only fits a Gallery upscale. Documented as "extend first, upscale last". Reword the message for generated clips, or allow it, and update the matching line in `docs/reference/troubleshooting.md`.
- **CUDA: the first LTX run prepares copies for minutes with no phase shown and Cancel waits.** The job card reads "Loading <model>..." throughout (`backends/cuda/video/backend.py`, `_prepared_weights` only logs; `load_model` takes no `on_phase`/`cancelled`, unlike the image loader's `saving_quant` phase).
- **A SIGKILL during a stored-copy save leaves a hidden multi-GB `.partial` folder**, swept only on a retry of the same target more than an hour later (`utils/stored_quant.py`, `sweep_stale_partials`). Applies to every stored-copy writer: image and video copies, the Mac H3 text-encoder copy, built models and conversions. Ctrl-C and ordinary errors clean up.
- **CUDA H3: a LoRA trained on a ComfyUI pruned checkpoint fails minutes in** with a raw `mat1 and mat2 shapes cannot be multiplied`; the AdaLN down factor is never shape-checked (`backends/cuda/video/h3/stored_copy.py`, `h3/adaln.py`). Only LoRAs that target AdaLN fail. Check the shape at load and name the cause.
- **macOS H3 refuses LoRAs with AdaLN modules** that CUDA accepts (`backends/mac/h3_video.py`), refused at load. CUDA's acceptance is certain for transformer-block AdaLN; the final layer's AdaLN goes through PEFT and isn't verified. Documented limitation; in hand in the Mac test.
- **A Stop during an image's last step still saves the picture** (found 2026-11-11 in the image editing Mac check). The job card says "You stopped the job", but the result is in the Gallery. Seen on a Klein edit on the Mac; the step check runs between steps, so a plain generation does the same (on CUDA the window is the VAE decode). Fix: check Stop once more before `save_image_stage` (`workflows/image_stages.py`).
- **The CLI takes seeds the Web UI can't hold.** `--seed` accepts any integer, while the Web UI's Seed field clamps a typed seed to 0–4294967295 (`frontend/src/features/workspace/settingsSpec.ts`). Reuse keeps a larger seed, but editing the field clamps it. SeedVR2 also folds seeds from 4293967296 up (`backends/cuda/seedvr2.py`, `_CORE_SEED_RANGE`). `config.yaml`'s `seed_max` only bounds random draws. Fix: refuse a larger `--seed` in the CLI, with the range in the message. Audio already refuses seeds above 2⁶³−1 (`check_seed`), so choose the bound deliberately.
- **Settings record the `{a|b}` prompt template, not the resolved choice** (`utils/provenance.py`), for images and for videos other than Extend, so Reuse rolls the choice again. The resolved text is only in an image's PNG Description. An Extend without `--prompt` rolls the source's template again when the source has no recorded scene; an Extend's own record is already resolved (`prompt_sent`). Fix: record the resolved text in both payloads, as Extend does.

- **LoRAs that don't fit fail late, silently or with the wrong message** (found 2026-10-28 while researching Discover LoRAs, sampling 1,710 Hugging Face LTX and MiniMax H3 headers). With swap they fail after the prompt is encoded, so minutes into a job; without swap at load.
  - **macOS LTX silently ignores** LoRAs with no `lora_A`/`lora_B` pairs (LyCORIS, kohya, LoKr) and ones that match no module: about 9% of sampled LTX files. This happens in the vendored attach (`packages/ltx_core_mlx/loader/lora_adapters.py`), which logs unmatched layers at info level only, and the handle is dropped in `ltx_pipelines_mlx/_base.py`. Silent in both the default unfused mode and the fused mode.
  - **Windows/Linux LTX gives misleading errors for prefix-less or kohya keys:** "Adapter name(s) … not in the list of present adapters", or at a weight other than 1.0 "does not support explicit LoRA scales" (`backends/cuda/video/backend.py::_apply_loras`). A file that matches no module is skipped with a warning, so it is as silent in the Web UI as on the Mac.
  - **Zero-match and partial-match warnings never reach the job card.** `web/web_runner.py` mutes the worker's output (`_MutedWorkerStreams`) and doesn't capture warnings.
  - **The docs over-claim.** `docs/concepts/loras.md` says an unsupported file or scale "fails before generation with a message saying why".

  Fix: one clear error per case, using the loader's own verdict, surfaced on the job card; correct the docs.

- **W4A8 checkpoints that keep their quantization records in the safetensors metadata are rejected** (found 2026-10-25, [checkpoint conversion](archive/ltx25-h3-checkpoint-conversion.md)). Some community LTX-2.5 W4A8+INT8 ConvRot files store them in `__metadata__._quantization_metadata` instead of `comfy_quant` tensors, and `utils/quantized_weights.py` reads only the `comfy_quant` form, so conversion fails with "stored as I8 with a scale but no quantization record" on every platform. The H3 converter uses the same reader. Fix: read the records from the metadata when no `comfy_quant` tensors are present.
- **Quantized LTX connectors always read as "can't tell"** (`connectors_status`, `converters/ltx_checkpoint.py`). Connectors that are quantized, or stored in anything but BF16, F16, F32 or F64 (FP8, say), return "can't tell" before any comparison; only exact-dtype connectors are hashed against stock's. So a Mac conversion writes about 4 GB of connectors that are usually stock's, and Windows/Linux uses stock's even when they were trained. Fix: decode the tensors and compare them with stock's within the format's quantization error, so most come out stock or changed.

- **Audio helpers on the Mac's 4-bit enhancer** (found 2026-11-08 in the [audio Mac checks](archive/audio-controls.md)):
  - **Fit to time can keep the model's own working as the script.** Once in the bench runs (Fit to 20 s, Fast) the answer was the script followed by the model counting characters; it was kept with only "Came out at about 1:34", and Generate would read it aloud. Fit also reads within 15% of the target in only 19 of 42 runs. The retry already exists: fix by having `_check_fit` (`utils/audio_writers.py`) report a problem above the tolerance, so a second far-off answer is refused; update `docs/guides/speech-and-sound.md` and the Fit tests to match.
  - **Smooth rhymes sometimes joins each pair of lines into one** and leaves the rhymes as they were, which changes the lines YuE2 sings. No bench check sees it: add one that the line count of each section is kept, or a line-count guard in the app's own check.
- **A cloned take's note is not shown in the Workspace.** "A cloned voice reads as recorded: the Delivery marks were left out." is saved with the take and shown in the Gallery and the CLI, but the Workspace result caption doesn't show it.
- **Qwen3-TTS on the Mac peaks at 12.0 GiB, twice the CUDA figure** (a built-in voice reading four parts of about 450 characters at Very slow). 4.3 GiB stays resident. mlx-audio 0.6.2 already decodes each part's codes in 300-frame windows (`chunked_decode`), so it is not yet known whether the talker loop or the codec decode drives the peak. Measure peak memory around each on a Mac before changing anything; a smaller decode window would mean calling the codec's decoder directly. It matters on 16 GB Macs.

## Code hygiene (no user impact)

- **Split the LTX backend.** `backends/cuda/video/backend.py` (about 1,600 lines) becomes LTX modules under `backends/cuda/video/ltx/` beside `h3/`, with no behaviour change. The plan and its conditions are step 2e of [LTX-2.5 and MiniMax H3](archive/ltx-2.5.md); its reload-test condition names a test that doesn't exist, so replace it or drop it. `backends/__init__.py`, `cuda/video/converted.py` and `docs/developer/backends.md` change in the same series.
- Dead code: `web_runner.WebRunner.get_job_result_path`, `job_contract.ACTIVE_STATUSES`, the job snapshot field `supports_controls` (duplicates `supported_controls`) and the `GET /docs/assets/{asset_name}` route (always 404 once installed) have no callers; `backends/cuda/image/backend._make_skip_callback` and the frontend `progress_text` SSE handler (no server event produces it) are unused. Used only by tests, so removing them means editing their tests: `utils/h3_memory.h3_extend_window_frames` (near-duplicate of `video_extend.window_frames`, without the frame-rule alignment) and `draft.reset()`.
- Duplicated helpers: `backends/mac/video.py` `_snapshot_download` repeats `utils/hf_snapshot.snapshot_download` (an import change; the call site already passes keywords); `workflows/video_stages.py` handles a `CalledProcessError` in the join and mux stages that `splice_clips` can never raise, while `strip_audio` and `embed_mp4_config` still raise it.
- `backends/cuda/video/h3/lora.py` docstring mentions a planning label ("C11's `load_copy`"; name `stored_copy.load_copy` instead); `h3/conditioning.py` imports the private `_weight_files` from `decode.py`.
- The Windows CUDA install command is hand-copied into `README.md` and `docs/get-started/install.md` while the code carries it as `CUDA_INSTALL_COMMAND` in `backends/cuda/driver.py`; a later index change (cu132 to the next) would leave the error message and the docs apart. A test in `tests/common/test_docs_reference.py` asserting both files contain the constant would tie them. Decision: skipped for v1.
- **Consider pydantic models for the user's per-file records** (and possibly the API bodies) once several user fields with constraints exist. Today a single bool is checked at the API boundary, and `AGENTS.md` says no pydantic, so that rule would change with it.

## Found during the docs overhaul

- **`--upscale-save-pre` help says `_pre`, the file gets `_preupscale`.** `image_cli.py` describes the suffix as `_pre`; `workflows/image_stages.py` writes `_preupscale`. `bench/transparent/__main__.py` (`find_render`) also still skips `_pre` stems, so it can pick a `_preupscale` file as the newest render.
- **The Vite dev proxy points at port 8765**, while `ziv ui` defaults to 8080 (`frontend/vite.config.ts`, `web/__init__.py`). The developer docs describe the 8765 workaround, so the fix is either the proxy target or those docs.
- **The Config page shows `HF_HOME` itself as the model cache** (`web/config_api.py`), but the models live in `HF_HOME/hub`, and it ignores `HF_HUB_CACHE`, which takes precedence. Use huggingface_hub's resolved `HF_HUB_CACHE`.
- **The Workspace First sigma hint contradicts the CLI help.** `SettingsPane.svelte` says a smaller first-step sigma may reduce the grey frame; the `--first-sigma` help and the docs say higher values (1.005 to 1.006) avoid it.
- **The convert form's "Copy instead of moving" is misnamed.** It copies the base model's files instead of linking them and never moves the checkpoint (`ModelsPage.svelte`, `converters/convert_checkpoint.py`).
- **The missing-Web-UI-packages message suggests `uv tool install --reinstall`** (`web/__init__.py`), which on Windows drops PyTorch's CUDA index. Point it at the documented repair, with the `--index` options.
- **The Audio tab's Reset tooltip lists fewer settings than Reset puts back.** The tooltip in `SettingsPane.svelte` names tempo, key, type, length, voice, batch and seed; the reset scope (`resetScope.ts`) also puts back the delivery and the Enhance options and clears the preset. The `resetSelections` docstring in `draft.svelte.ts` has the same gap.
- **`ziv-image -m`'s help undersells aliases, and the epilogs suggest folder paths.** It reads "Path to the base model (Hugging Face format)", and `-m models/my-model` (`image_cli.py`) and `-m models/ltx-mlx` (`video_cli.py`) look relative to the current folder rather than names in the data folder. Model the image help on the video help.
- **The Web UI branches on model families in several places**, against the aim that capabilities come from the metadata: `web/model_status.py`, `web/lora_fit.py`, `web/workspace_api.py`, `web/upscale_api.py`, `ModelsPage.svelte`, `lib/state/memoryFit.ts` and `features/workspace/discover/discoverView.ts`, among others. The developer docs name them as known exceptions.
- **The Models page hard-codes the converter's model types** (`ModelsPage.svelte`, including the LTX and H3 type lists), which must match `MODEL_TYPES` in `converters/convert_checkpoint.py` by hand; no test compares them. They agree today.

## Accepted as is

- `--host local` has no login; anyone on the network can use the UI and its file routes, including reading any YAML through the prompt-file document route. Communicated in [Other devices](../docs/web-ui/devices.md).
- A hand-broken `config.yaml`, or an output folder on an unplugged drive, makes every page answer a bare "Internal Server Error". Judged not worth mitigating.
